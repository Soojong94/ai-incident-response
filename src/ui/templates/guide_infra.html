🏗️ 인프라 사전 준비 가이드

NCP 계정에 1회 셋업. 새 사이트 추가 시엔 단계 3 (OBS 버킷) · 4 (WMS 시나리오) · 5 (사이트 등록) 만 반복.

1

NCP 루트 인증키 발급

OBS 객체 접근에는 루트 계정 키가 필요합니다 (IAM 키는 OBS 권한 부여 불가).

콘솔 → 계정 및 보안 관리 → 보안관리 → 접근관리
  1. 「API 인증키 관리」 또는 「Access Key 발급」 메뉴 진입
  2. 새 키 생성 → Access Key / Secret Key 두 값 안전한 곳에 저장
  3. 본 플랫폼의 사이트 설정 「NCP API 키」 카드에 입력 (Fernet 암호화 저장)
⚠️ Secret Key 는 발급 시점에만 노출됩니다. 분실하면 재발급 필요.
2

Cloud Log Analytics (CLA) Agent 설치

알람 대상 호스트에 로그 수집 에이전트를 설치. NCP 콘솔이 설치 명령을 자동 생성해줍니다.

콘솔 → Cloud Log Analytics → Management → Agent 설치
  1. 대상 호스트의 OS 선택 (Linux / Windows)
  2. 콘솔에서 자동 생성된 설치 스크립트 복사
  3. 대상 호스트에서 SSH 접속 → 그대로 붙여넣기 실행
  4. 「Agent 상태」 화면에서 새 호스트가 Active 로 보이는지 확인
logTypes 기본값: 본 시스템 CF 코드는 SYSLOG, nginx_access, nginx_error, security_log 를 수집. 다른 로그 종류가 필요하면 cf_wms_poll/main.py 의 CLA_LOG_TYPES 상수 수정.
3

Object Storage 버킷 생성

CLA SearchLogs Export 가 결과 JSON 을 저장할 OBS 버킷. 사이트마다 분리 또는 폴더로 구분.

콘솔 → Object Storage → 버킷 관리 → + 버킷 생성
버킷 이름사이트 식별 가능한 이름 (예: team1-demo, customer-a-logs)
리전KR (한국)
공개 설정Private — 루트 키로만 접근
라이프사이클운영 정책에 따라 (권장: 30~90일 자동 삭제 — 디스크 비용 vs 회고 트레이드오프)
버킷 이름은 본 플랫폼의 사이트 설정 「매칭 + CF 식별자」 카드의 OBS 버킷 필드에 입력. 인시던트 매칭 1차 기준입니다.
4

WMS (Web Monitoring Service) 시나리오 등록

알람 조건 정의. 사이트당 시나리오 1개, 여러 사이트면 여러 시나리오 + 여러 Cron 트리거.

콘솔 → Web Monitoring Service → 시나리오 관리 → + 시나리오 생성
시나리오 종류URL Error 시나리오 (현재 본 시스템 기준)
모니터링 대상 URL알람 대상 호스트의 health-check URL
알람 조건최근 5~30분 윈도우 안에 errorCount ≥ 3 (운영). 테스트 사이트는 ≥ 1 로 낮춰서 사용
발급된 SCENARIO_ID시나리오 생성 후 발급되는 숫자 — 본 플랫폼 사이트 설정 「WMS scenario ID」 필드에 입력
Cloud Insight 는 메트릭 종류가 다양해서(서버 리소스 / 커스텀 메트릭 등) 미래 고도화 영역. 현재는 WMS URL Error 만 지원.
5

본 플랫폼에 사이트 등록

위 단계에서 얻은 값들을 사이트 설정에 입력.

본 플랫폼 → 사이트 관리 → + 사이트 추가
사이트 이름대시보드에 보일 이름 (예: team1-demo)
resource_name 패턴알람 페이로드의 resourceName 매칭용 글로브 (예: team1-*)
OBS 버킷단계 3 의 버킷 이름
WMS scenario ID단계 4 의 발급된 번호
NCP API 키단계 1 의 Access / Secret Key — 「사이트 수정」 토글 후 입력하면 암호화 저장
아키텍처 (선택)인프라 구성 요약 markdown — AI 분석 prompt 컨텍스트로 자동 주입
수신자사이트별 알림 받을 이메일/Slack (심각도별 권한 체크)
Rate limit윈도우/임계값. 운영 5분 3건 기본, 비상 모드 ON 시 무시
