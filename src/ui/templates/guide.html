📘 사용 가이드

서버에 에이전트(Alloy)를 설치해 장애를 자동으로 감지·분석하는 방법과, 이 대시보드 사용법을 안내합니다.

바로가기   ① 동작 원리 ② 서버 추가(일반) ③ 폐쇄망 서버 ④ 사이트 사용법 ⑤ 장애 확인 ⑥ 자주 묻는 질문

① 동작 원리 — 한눈에

대상 서버에 Grafana Alloy 하나만 설치하면 됩니다. 메트릭(CPU/메모리/디스크)과 로그를 중앙으로 계속 보내고, 임계값을 넘으면 그 순간의 로그를 모아 AI가 원인을 분석해 이 대시보드와 이메일로 알려줍니다.

[대상 서버] Alloy ──상시 전송(메트릭+로그)──► 중앙 서버 │ CPU 80% 5분 초과 등 → 자동 발화 ▼ 직전 5분 로그 수집 → AI 분석 → 이 대시보드 + 이메일
기존 방식(클라우드별 설정·NAT·Cloud Function)이 전부 필요 없어졌습니다. 서버에서 인터넷으로 나가는 길만 있으면 됩니다. AWS·NCP·KT·온프렘 어디든 동일.

② 새 서버 추가하기 (인터넷 되는 일반 서버)

아래 3단계면 끝입니다. 서버마다 다른 건 이름(SERVER_NAME) 한 곳뿐입니다.

1Alloy 설치

Ubuntu / Debian

sudo apt-get install -y curl unzip
curl -sL -o alloy.zip https://github.com/grafana/alloy/releases/latest/download/alloy-linux-amd64.zip
sudo unzip -o alloy.zip -d /usr/local/bin/ && sudo chmod +x /usr/local/bin/alloy-linux-amd64

Rocky / RHEL 계열 (curl은 기본 제공)

sudo dnf install -y unzip
curl -sL -o alloy.zip https://github.com/grafana/alloy/releases/latest/download/alloy-linux-amd64.zip
sudo unzip -o alloy.zip -d /usr/local/bin/ && sudo chmod +x /usr/local/bin/alloy-linux-amd64

Windows: 릴리스 페이지에서 alloy-windows-amd64.exe.zip 받아 압축 해제.

2config.alloy 작성

아래를 config.alloy로 저장하고 SERVER_NAME과 중앙 주소만 바꾸세요. 이 이름이 그대로 대시보드의 사이트 이름·장애 호스트가 됩니다.

// ── 메트릭 (Windows는 prometheus.exporter.windows) ──
prometheus.exporter.unix "n" { }
prometheus.scrape "n" {
  targets = prometheus.exporter.unix.n.targets
  forward_to = [prometheus.relabel.h.receiver]
  scrape_interval = "15s"
}
prometheus.relabel "h" {
  forward_to = [prometheus.remote_write.c.receiver]
  rule { target_label = "host"  replacement = "SERVER_NAME" }   // ← 서버 이름
}
prometheus.remote_write "c" {
  endpoint { url = "http://<중앙IP>:8428/api/v1/write" }       // ← 중앙 주소
}

// ── 로그 (journald + /var/log 전체. 앱 경로 따로 안 받아도 됨) ──
local.file_match "f" { path_targets = [{ "__path__" = "/var/log/**/*.log" }] }
loki.source.file "f" { targets = local.file_match.f.targets  forward_to = [loki.process.h.receiver] }
loki.process "h" {
  forward_to = [loki.write.c.receiver]
  stage.static_labels { values = { host = "SERVER_NAME", job = "syslog" } }
}
loki.write "c" {
  endpoint { url = "http://<중앙IP>:9428/insert/loki/api/v1/push" }
}

3실행 + 방화벽

alloy-linux-amd64 run config.alloy --storage.path /var/lib/alloy

중앙 방화벽(ACG)에 이 서버 IP로 8428(메트릭)·9428(로그) 인바운드를 한 번 열어주면 됩니다. 서버에 별도 등록은 필요 없습니다 — 보내기 시작하면 중앙이 바로 받습니다.

운영에선 systemd 서비스로 등록하세요. 설치 스크립트로 SERVER_NAME만 받아 자동화하면 서버 수가 늘어도 동일하게 찍어낼 수 있습니다.

③ 폐쇄망 서버 (인터넷이 안 되는 경우)

인터넷 아웃바운드가 막힌 서버는 중앙에 직접 못 보냅니다. 고객망 안에 인터넷 되는 서버 1대를 "중계(relay) 서버"로 세우고, 폐쇄 서버들은 그쪽으로만 보냅니다.

[폐쇄 서버] Alloy ──내부망──► [중계 서버] ──인터넷──► 중앙

중계 서버 (인터넷 되는 1대)

monitoring/alloy/relay-server.alloy 사용 — 내부에서 메트릭(:9999)·로그(:9998)를 받아 중앙(8428/9428)으로 넘깁니다. (이 서버 자신도 일반 서버처럼 모니터링하려면 ②의 수집 블록을 함께 넣으면 됩니다 → 그러면 "일반+중계 겸용")

폐쇄 서버

monitoring/alloy/relay-agent.alloy 사용 — ②와 똑같되 전송 대상만 중계 서버의 내부 IP(:9999/:9998)로 지정.

중앙 방화벽은 중계 서버 IP만 열면 됩니다. 폐쇄 서버는 IP 등록 불필요. 즉 에이전트는 결국 두 종류예요 — ⓐ 중앙으로 직접 보내는 서버(겸용으로 중계도 가능) / ⓑ 중계 서버로 보내는 폐쇄 서버.

④ 사이트 사용법 (사이트 관리)

사이트는 서버(들)를 묶는 단위입니다. 누구에게 알림을 보낼지, 어떤 맥락으로 분석할지를 여기서 정합니다.

자동 생성

새 서버에서 첫 장애가 들어오면 그 이름으로 사이트가 자동 생성됩니다. 미리 만들 필요는 없지만, 이메일을 받으려면 수신자를 미리 등록하는 걸 권장합니다.

① 수신자 등록 (이메일/Slack)

사이트 상세에서 수신자를 추가하고, 심각도별 수신 여부(Critical/High/Medium/Low)를 켭니다. 분석이 끝나면 해당 심각도를 받기로 한 사람에게만 발송됩니다.

② 매칭 규칙

여러 서버를 한 사이트로 묶으려면 resource 패턴(글로브, 예: web-prod-*)을 지정하세요. 장애의 호스트 이름이 패턴에 맞으면 그 사이트로 분류됩니다.

③ 알림 폭주 방지 (rate-limit)

같은 사이트에서 짧은 시간에 장애가 쏟아지면 일정 횟수 초과분은 분석·알림을 자동으로 건너뜁니다(기본 5분 3건). 장애 대응 중 시끄럽지 않게 해줍니다. 비상 시 끌 수도 있습니다.

④ 인프라 구조 메모 → 분석 품질↑

사이트에 인프라 구조(예: "nginx→was 2대→MySQL, Redis 캐시")를 적어두면 AI가 분석할 때 그 맥락을 참고해 더 정확해집니다.

⑤ 사이트 메모 + 학습

운영 메모를 남길 수 있고, AI가 반복되는 원인을 자동으로 누적합니다. 분석 결과에 👍을 누르면 검증된 메모로 승격되어 다음 분석에 활용됩니다.

⑤ 장애 확인하기

  • 장애 목록: 발생 서버·심각도·AI 판단 원인·상태를 한눈에. 검색/필터 가능.
  • 장애 상세: 클릭하면 수집된 실제 로그와 AI 분석 전문(원인 분류·상세·영향 범위·즉시 조치·재발 방지)을 봅니다.
  • 피드백: 분석이 정확하면 👍 — 사이트 메모로 승격되어 학습됩니다.
  • 상태: processing(분석 중) → analyzed(완료) / ai_failed(분석 실패) / suppressed(폭주 억제).

⑥ 자주 묻는 질문

로그가 중앙에 계속 쌓이나요?

네, 짧게(기본 7일) 보관하는 롤링 버퍼입니다. 장애 시 그중 직전 5분만 분석에 씁니다. 영구 보관은 아닙니다.

Grafana 화면이 필요한가요?

아니요. 메트릭은 임계 판단용으로만 저장하고, 사람이 보는 화면은 이 대시보드입니다.

서버마다 설정을 다 해야 하나요?

config는 서버마다 있어야 하지만 이름 한 줄만 다릅니다. 설치 스크립트로 자동화하세요.

새 서버를 중앙에 먼저 등록해야 하나요?

아니요. 보내기 시작하면 바로 받습니다. 방화벽(ACG)에 IP만 열면 됩니다.
