📘 설치 가이드

① 설치 ② 알람 · 운영

서버에 에이전트(Alloy)를 설치해 장애를 자동 감지·분석하는 방법입니다. 내 서버 유형(공인망/폐쇄망)을 ②에서 고르고, 해당 케이스(③ 또는 ④)를 그대로 따라 하면 됩니다. (알람이 어떻게 동작하는지는 ② 알람·운영)

바로가기   ① 동작 원리 ② 내 서버 유형 고르기 ③ 케이스 A — 공인망(직접) ④ 케이스 B — 폐쇄망 ⑤ Windows ⑥ 사이트·그룹 ⑦ 장애 확인 ⑧ FAQ

① 동작 원리 — 한눈에

대상 서버에 Grafana Alloy 하나만 설치하면 됩니다. 메트릭(CPU/메모리/디스크)과 로그를 중앙으로 계속 보내고, 임계값을 넘으면 그 순간의 로그를 모아 AI가 원인을 분석해 이 대시보드와 이메일로 알려줍니다.

[대상 서버] Alloy ──상시 전송(메트릭+로그, HTTPS)──► 중앙 서버 │ CPU 80% 5분 초과 등 → 자동 발화 ▼ 직전 5분 로그 수집 → AI 분석 → 이 대시보드 + 이메일
중앙으로의 전송은 HTTPS(443) + 아이디/비밀번호(basic-auth)로 보호됩니다. 로그가 평문으로 인터넷을 타지 않습니다. 클라우드 종류(AWS·NCP·KT·온프렘) 무관하게 동일합니다.

② 내 서버는 어떤 유형인가요?

딱 2가지뿐입니다. 아래로 판단하세요.

이 서버가 인터넷(밖)으로 나갈 수 있나? ├─ 예 → 케이스 A: 공인망(직접) … 중앙으로 바로 전송 → ③ 으로 └─ 아니오(폐쇄망) → 케이스 B: 폐쇄망 같은 사내망에 인터넷 되는 서버 1대를 "게이트웨이"로 세우고 그쪽으로 보냄 → ④ 로
즉 에이전트 "종류"는 직접 / 폐쇄망 2가지이고, 게이트웨이는 직접 서버가 폐쇄망 서버들의 출구(중계) 역할을 겸하는 것입니다. 모든 케이스에서 중앙엔 사전 등록 불필요 — 보내기 시작하면 사이트 관리에 자동 등장합니다.

모든 케이스 공통 — 미리 알아둘 값

  • RESOURCE_NAME : 이 서버 이름(=대시보드 사이트). 예 web-prod-01
  • GROUP_NAME : 상위 그룹(같은 값끼리 한 묶음). 보통 고객사/게이트웨이 이름. 예 tbit-air
  • INGEST_USER / INGEST_PASS : 중앙에서 발급한 인제스트 자격(기본 계정 agent). 관리자에게 문의.
  • 중앙 주소 : https://tbit-msp.kro.kr (환경에 맞게)

③ 케이스 A — 공인망(직접) 서버

인터넷으로 나갈 수 있는 일반 Linux 서버. 아래 5단계면 끝이고, 서버마다 바꾸는 건 env 파일뿐(config는 모든 서버 동일)입니다.

1Alloy 설치

sudo apt-get install -y unzip            # Rocky/RHEL: sudo dnf install -y unzip
curl -sL -o /tmp/alloy.zip https://github.com/grafana/alloy/releases/latest/download/alloy-linux-amd64.zip
sudo unzip -oq /tmp/alloy.zip -d /usr/local/bin/ && sudo chmod +x /usr/local/bin/alloy-linux-amd64
sudo mkdir -p /etc/alloy-air /var/lib/alloy-air

2config.alloy (그대로 복사 — 안 바꿔도 됨)

sudo tee /etc/alloy-air/config.alloy >/dev/null <<'EOF'
// 메트릭 (CPU/메모리/디스크 등)
prometheus.exporter.unix "host" { }
prometheus.scrape "host" {
  targets = prometheus.exporter.unix.host.targets
  forward_to = [prometheus.relabel.add.receiver]
  scrape_interval = "15s"
}
prometheus.relabel "add" {
  forward_to = [prometheus.remote_write.central.receiver]
  rule {
    target_label = "host"
    replacement  = sys.env("RESOURCE_NAME")
  }
  rule {
    target_label = "group"
    replacement  = sys.env("GROUP_NAME")
  }
}
prometheus.remote_write "central" {
  endpoint {
    url = sys.env("CENTRAL_VM_URL")
    basic_auth {
      username = sys.env("INGEST_USER")
      password = sys.env("INGEST_PASS")
    }
  }
}
// 로그 (journald + /var/log 전체 — 앱 경로 따로 안 받아도 됨)
loki.source.journal "j" {
  max_age = "12h"
  labels = { job = "journal" }
  forward_to = [loki.process.add.receiver]
}
local.file_match "f" { path_targets = [{ "__path__" = "/var/log/**/*.log" }] }
loki.source.file "f" {
  targets = local.file_match.f.targets
  forward_to = [loki.process.add.receiver]
}
loki.process "add" {
  forward_to = [loki.write.central.receiver]
  stage.static_labels { values = { host = sys.env("RESOURCE_NAME"), group = sys.env("GROUP_NAME") } }
}
loki.write "central" {
  endpoint {
    url = sys.env("CENTRAL_VL_URL")
    basic_auth {
      username = sys.env("INGEST_USER")
      password = sys.env("INGEST_PASS")
    }
  }
}
EOF

3env 파일 — 여기만 내 값으로

sudo tee /etc/default/alloy-air >/dev/null <<'EOF'
RESOURCE_NAME=web-prod-01                                   # ← 이 서버 이름
GROUP_NAME=tbit-air                                         # ← 상위 그룹(묶을 이름)
CENTRAL_VM_URL=https://tbit-msp.kro.kr/vm/api/v1/write
CENTRAL_VL_URL=https://tbit-msp.kro.kr/vl/insert/loki/api/v1/push
INGEST_USER=agent
INGEST_PASS=중앙에서-받은-비밀번호                            # ← 관리자에게 받은 값
EOF

4systemd 등록 + 실행 (모든 케이스 공통)

sudo tee /etc/systemd/system/alloy-air.service >/dev/null <<'EOF'
[Unit]
Description=Grafana Alloy (AI incident agent)
After=network-online.target
[Service]
EnvironmentFile=/etc/default/alloy-air
ExecStart=/usr/local/bin/alloy-linux-amd64 run /etc/alloy-air/config.alloy --storage.path=/var/lib/alloy-air --server.http.listen-addr=127.0.0.1:12345
Restart=always
User=root
[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload && sudo systemctl enable --now alloy-air
sudo systemctl status alloy-air --no-pager        # active (running) 확인

5방화벽 + 확인

중앙 방화벽(ACG/보안그룹)에 이 서버 공인 IP로 443 인바운드만 한 번 열면 됩니다. 그다음 사이트 관리를 열면 이 서버가 자동으로 등장합니다(🌐 그룹 카드 → 클릭 → 서버).

에러 확인: journalctl -u alloy-air -n 30 에 401(자격 틀림)·x509(인증서)·refused(방화벽)만 없으면 정상입니다. (/var/log/installer 류 stat 에러는 무해)

④ 케이스 B — 폐쇄망 (인터넷이 안 되는 서버)

인터넷이 막힌 서버는 중앙에 직접 못 보냅니다. 같은 사내망에 인터넷 되는 서버 1대를 "게이트웨이"로 세우고, 폐쇄망 서버는 그쪽으로만 보냅니다.

[폐쇄망 서버] Alloy ──사내망 9999/9998──► [게이트웨이] ──HTTPS──► 중앙 (게이트웨이는 자기 자신도 수집)
설치 순서: 게이트웨이(④-1) 먼저 → 폐쇄망 서버(④-2). 중앙 방화벽엔 게이트웨이 공인 IP로 443만 열면 됩니다(폐쇄망 서버 IP 불필요). 그룹은 게이트웨이가 자기+중계분에 GROUP_NAME을 찍어 폐쇄망 서버까지 자동으로 같은 그룹이 됩니다.

④-1. 게이트웨이 (인터넷 되는 1대)

1) Alloy 설치는 ③-1과 동일. 2) config는 아래(자기수집 + 폐쇄망 중계 겸용):

sudo tee /etc/alloy-air/config.alloy >/dev/null <<'EOF'
// 자기 자신 메트릭
prometheus.exporter.unix "self" { }
prometheus.scrape "self" {
  targets = prometheus.exporter.unix.self.targets
  forward_to = [prometheus.relabel.self.receiver]
  scrape_interval = "15s"
}
prometheus.relabel "self" {
  forward_to = [prometheus.remote_write.central.receiver]
  rule {
    target_label = "host"
    replacement  = sys.env("RESOURCE_NAME")
  }
  rule {
    target_label = "group"
    replacement  = sys.env("GROUP_NAME")
  }
}
// 자기 로그 (journald = 시스템 전체 + /var/log 파일)
loki.source.journal "sj" {
  max_age = "12h"
  forward_to = [loki.process.self.receiver]
}
local.file_match "sf" { path_targets = [{ "__path__" = "/var/log/**/*.log" }] }
loki.source.file "sf" {
  targets = local.file_match.sf.targets
  forward_to = [loki.process.self.receiver]
}
loki.process "self" {
  forward_to = [loki.write.central.receiver]
  stage.static_labels { values = { host = sys.env("RESOURCE_NAME"), job = "syslog", group = sys.env("GROUP_NAME") } }
}
// ↓ 폐쇄망 서버에서 받기(9999/9998) → group 라벨 찍어 중앙으로
prometheus.receive_http "in" {
  http {
    listen_address = "0.0.0.0"
    listen_port    = 9999
  }
  forward_to = [prometheus.relabel.relay.receiver]
}
prometheus.relabel "relay" {
  forward_to = [prometheus.remote_write.central.receiver]
  rule {
    target_label = "group"
    replacement  = sys.env("GROUP_NAME")
  }
}
prometheus.remote_write "central" {
  endpoint {
    url = sys.env("CENTRAL_VM_URL")
    basic_auth {
      username = sys.env("INGEST_USER")
      password = sys.env("INGEST_PASS")
    }
  }
}
loki.source.api "lin" {
  http {
    listen_address = "0.0.0.0"
    listen_port    = 9998
  }
  forward_to = [loki.process.relay.receiver]
}
loki.process "relay" {
  forward_to = [loki.write.central.receiver]
  stage.static_labels { values = { group = sys.env("GROUP_NAME") } }
}
loki.write "central" {
  endpoint {
    url = sys.env("CENTRAL_VL_URL")
    basic_auth {
      username = sys.env("INGEST_USER")
      password = sys.env("INGEST_PASS")
    }
  }
}
EOF

3) env — 게이트웨이 자기 값:

sudo tee /etc/default/alloy-air >/dev/null <<'EOF'
RESOURCE_NAME=gw-01                                         # ← 게이트웨이 서버 이름
GROUP_NAME=tbit-air                                         # ← 이 그룹 이름(폐쇄망 서버도 여기 묶임)
CENTRAL_VM_URL=https://tbit-msp.kro.kr/vm/api/v1/write
CENTRAL_VL_URL=https://tbit-msp.kro.kr/vl/insert/loki/api/v1/push
INGEST_USER=agent
INGEST_PASS=중앙에서-받은-비밀번호
EOF

4) systemd 실행은 ③-4와 동일. 5) 사내 방화벽에 폐쇄망 서버 → 게이트웨이 9999/9998 허용:

sudo ufw allow from 폐쇄망서버IP to any port 9999 proto tcp
sudo ufw allow from 폐쇄망서버IP to any port 9998 proto tcp
# (firewalld면 rich-rule, 클라우드면 보안그룹/ACG에서 사내 인바운드 9999/9998 허용)

④-2. 폐쇄망 서버

인터넷이 없으니 Alloy 바이너리를 게이트웨이에서 복사해 넣습니다.

1) 게이트웨이에서 폐쇄망 서버로 전송:

scp /usr/local/bin/alloy-linux-amd64 사용자@폐쇄망서버IP:/tmp/

2) 폐쇄망 서버에서 설치 + config(게이트웨이로만 전송):

sudo install -m 0755 /tmp/alloy-linux-amd64 /usr/local/bin/alloy-linux-amd64
sudo mkdir -p /etc/alloy-air /var/lib/alloy-air
sudo tee /etc/alloy-air/config.alloy >/dev/null <<'EOF'
prometheus.exporter.unix "n" { }
prometheus.scrape "n" {
  targets = prometheus.exporter.unix.n.targets
  forward_to = [prometheus.relabel.h.receiver]
  scrape_interval = "15s"
}
prometheus.relabel "h" {
  forward_to = [prometheus.remote_write.relay.receiver]
  rule {
    target_label = "host"
    replacement  = sys.env("RESOURCE_NAME")
  }
}
prometheus.remote_write "relay" { endpoint { url = sys.env("GATEWAY_VM_URL") } }
loki.source.journal "j" {
  max_age = "12h"
  forward_to = [loki.process.h.receiver]
}
local.file_match "f" { path_targets = [{ "__path__" = "/var/log/**/*.log" }] }
loki.source.file "f" {
  targets = local.file_match.f.targets
  forward_to = [loki.process.h.receiver]
}
loki.process "h" {
  forward_to = [loki.write.relay.receiver]
  stage.static_labels { values = { host = sys.env("RESOURCE_NAME"), job = "syslog" } }
}
loki.write "relay" { endpoint { url = sys.env("GATEWAY_VL_URL") } }
EOF

3) env — 전송 대상이 게이트웨이 사내 IP(그룹은 게이트웨이가 찍으므로 여기엔 없음):

sudo tee /etc/default/alloy-air >/dev/null <<'EOF'
RESOURCE_NAME=app-closed-01                                 # ← 이 폐쇄망 서버 이름
GATEWAY_VM_URL=http://게이트웨이사내IP:9999/api/v1/metrics/write
GATEWAY_VL_URL=http://게이트웨이사내IP:9998/loki/api/v1/push
EOF

4) systemd 실행은 ③-4와 동일. 폐쇄망 서버는 인바운드 22(SSH)만 열면 되고, 나가는 건 게이트웨이 9999/9998뿐입니다.

확인: 사이트 관리에서 게이트웨이 그룹(예 tbit-air) 카드 안에 게이트웨이와 폐쇄망 서버가 함께 보이면 성공.

⑤ Windows 서버는?

흐름은 동일하고 메트릭/로그 수집 블록만 Windows용으로 바꿉니다. 릴리스에서 alloy-windows-amd64.exe.zip를 받고, config의 수집부를 아래로 교체(전송/basic_auth/group 부분은 위와 동일):

prometheus.exporter.windows "host" { }
prometheus.scrape "host" {
  targets = prometheus.exporter.windows.host.targets
  forward_to = [prometheus.relabel.add.receiver]
  scrape_interval = "15s"
}
// 로그: 윈도우 이벤트 로그
loki.source.windowsevent "win" {
  eventlog_name = "Application"
  forward_to = [loki.process.add.receiver]
}

나머지(prometheus.relabel.add, remote_write, loki.process.add, loki.write)는 ③과 동일합니다. 실행은 Windows 서비스(nssm 등) 또는 alloy-windows-amd64.exe run config.alloy.

⑥ 사이트 · 그룹 사용법 (사이트 관리)

서버(host) = 사이트가 기본 단위이고, 같은 게이트웨이(=공인IP) 뒤의 서버들은 상위 그룹으로 묶여 보입니다.

자동 등록 · 그룹 드릴인

에이전트가 데이터를 보내기 시작하면 — 장애가 없어도 — 사이트 관리에 서버가 자동 등록됩니다. 상위 화면은 🌐 그룹 카드로 보이고, 클릭하면 그 그룹의 서버 카드들로 들어갑니다(그룹 = GROUP_NAME).

① 수신자 등록 (이메일/Slack)

사이트 상세에서 수신자를 추가하면 분석 완료 시 이메일/Slack으로 발송됩니다. (수신자 없으면 ALERT_EMAIL 폴백)

② 매칭 패턴

여러 서버를 한 사이트로 합치려면 글로브 패턴(예 web-prod-*)을 지정. (그룹=보기용 묶음, 패턴=한 사이트로 통합 — 별개 개념)

③ 알림 폭주 방지 · ④ 아키텍처 메모

짧은 시간 장애 폭주 시 초과분 자동 억제(기본 5분 3건). 사이트에 인프라 구조를 적어두면 AI 분석 정확도↑.

⑤ 서버 로그 다운로드 (7일 보관)

사이트 상세 "서버 로그"에서 최근 7일 raw 로그를 기간별 미리보기/.log 다운로드.

⑦ 장애 확인하기

  • 장애 목록: 발생 서버·심각도·AI 원인·상태를 한눈에. 검색/필터.
  • 장애 상세: 수집된 실제 로그 + AI 분석 전문(원인·영향·즉시조치·재발방지).
  • 상태: processing→analyzed / ai_failed / suppressed(폭주 억제).

⑧ 자주 묻는 질문

config가 서버마다 달라야 하나요?

아니요. config는 케이스(직접/게이트웨이/폐쇄망)별로 동일하고, env 파일만 서버마다 다릅니다(이름·그룹·대상주소).

새 서버를 중앙에 먼저 등록해야 하나요?

아니요. 보내기 시작하면 바로 받고 사이트 관리에 자동 등록됩니다. 방화벽에 IP로 443만 열면 됩니다.

여러 서버를 하나로 묶어서 보려면?

GROUP_NAME을 같은 값으로 주면 한 그룹 카드로 묶입니다. 폐쇄망 서버는 게이트웨이가 대신 찍어주므로 손댈 필요 없습니다.

로그는 영구 보관인가요?
