종류발화 조건출처

CPU/메모리/디스크는 서버마다 독립입니다 — 셋 다 임계 초과면 각각 따로 뜹니다.

알람이 뜨면 그 host의 직전 5분 로그를 모아 AI가 원인을 분석합니다. (CPU 과부하처럼 로그를 안 남기는 자원 알람은 로그가 빈약할 수 있어요)

② 임계값 설정 (서버별)

사이트 관리 → 서버 → 수정 → "알람 임계값"에서 CPU/메모리/디스크 %와 지속시간(초)을 정합니다. 저장하면 즉시 반영(룰 자동 생성·리로드).

1분 평균 + 지속시간

CPU는 1분 평균으로 보고, 지속시간만큼 연속 초과해야 발화합니다 — 순간 스파이크로 시끄럽지 않게.

예) CPU 80% + 지속 180초 = "1분 평균 80%가 3분 연속" 시 발화.

끄기 / 미감시

특정 지표 칸을 비우면 그 지표는 미감시. "알람 켜기"를 끄면 그 서버는 임계값·무응답 모두 안 울립니다.

새로 들어온 서버는 기본 ON(CPU 85 / 메모리 90 / 디스크 85)으로 감시됩니다. 특정 서버만 빼려면 그 서버에서 알람을 끄세요.

③ 장애 1건으로 묶기 (중복 방지)

같은 알람이 계속 켜져 있으면 알림 시스템이 ~5분마다 재통지합니다. 그때마다 장애를 새로 만들지 않도록, 다음이면 기존 1건을 유지합니다:

  • 같은 서버 + 같은 알람이고
  • 아직 미해결(resolved 전)이며
  • 최근 1시간 내 생성된 장애가 있을 때
짧은 부하(≤5분) → 장애 1건 (재통지 틈 없음) 오래 지속(10분+) → 5분마다 재통지가 와도 전부 1건으로 묶임 알람 해제됨 → 다음에 또 켜지면 새 장애 1건
혼동 주의: "5분"은 알림 폭주 방지(아래) 얘기고, 중복 방지는 "같은 알람 미해결이면 1건"(1시간 기준)입니다.

④ 자동 해제 (resolved)

알람이 풀리면(CPU가 임계 아래로, 서버가 다시 응답 등) 자동으로 장애가 resolved(초록) 처리됩니다.

  • 대시보드에서 해결된 것으로 보이고
  • 진행 중이던 에스컬레이션도 즉시 중지됩니다.

즉 사람이 일일이 닫지 않아도 상태가 따라옵니다. (서버 무응답도 복구되면 자동 resolved)

⑤ 알림 받기 (수신자)

사이트 상세 → 수신자 관리에서 이메일/Slack을 등록합니다. 등록만 하면 됩니다(심각도 구분 없음).

모드동작
기본 (에스컬레이션 OFF)장애 발생 시 등록 수신자 전원에게 즉시 발송
에스컬레이션 ON단계 0부터 차례로 — 미확인 시 다음 단계로 승격(⑥)

수신자가 한 명도 없으면 ALERT_EMAIL(폴백)로 발송됩니다.

⑥ 에스컬레이션 + 확인(ack)

사이트 상세 → 에스컬레이션 켜기 + 단계 간 지연(분) 설정. 수신자마다 단계를 부여합니다(0 = 1차 담당, 숫자↑ = 상위, 마지막 = C레벨).

장애 발생 → 단계 0 발송 → (지연 내 '확인' 없으면) 단계 1 → (지연) 단계 2 → … → 최고 단계 → 그래도 미확인이면 다시 0부터 반복 멈춤 = '확인(ack)' / 알람 해제(resolved) / 24시간 경과

"확인" 버튼

알림 메일에 "✓ 확인 (에스컬레이션 중지)" 버튼이 있습니다. 누르면(로그인 불필요) 그 즉시 에스컬레이션이 멈추고, 누가/언제 확인했는지 대시보드에 남습니다.

대시보드 표시

장애 목록·상세에 ✓ 확인됨 (확인자·시각) 또는 미확인 · 단계N 으로 보입니다.

조직 / 서버

장애·알림·메일 모두 🏢 조직(그룹) · 🖥 서버(host) 가 함께 표시됩니다. 메일 제목도 [조직/서버]. 그룹은 에이전트의 GROUP_NAME 으로 묶입니다.

알림 폭주 방지 (rate-limit)

한 사이트에서 짧은 시간(기본 5분)에 장애가 임계(기본 3건)를 넘으면 초과분을 자동 억제(suppressed)합니다. 장애 대응 중 알림 폭탄 방지. (사이트별 조절 가능, 비상 모드로 끌 수 있음)

⑧ 운영 · 테스트 팁

부하 테스트

대상 서버에서 (설치 없이) CPU를 채워 발화 확인:

for i in $(seq $(nproc)); do yes >/dev/null & done # 부하 pkill yes # 종료

빠른 확인용으로 그 서버의 임계값을 낮추고 지속시간을 짧게(예 CPU 30% / 30초) 해두면 1~2분 내 발화합니다. 끝나면 원복.

한 사이클로 보기

부하 → 장애 1건(조직/서버·로그 포함) → 에스컬레이션 0→1→2→반복 → 메일 "확인" → 중지 → pkill yes → 자동 resolved.

정리

테스트 장애를 한꺼번에 비우려면 운영자가 중앙에서 scripts/cleanup.sh 실행, 또는 장애 목록에서 개별/일괄 삭제.
