대상 서버에 까는 건 Grafana Alloy 하나뿐이고, 중앙은 docker-compose.yml 하나로 수집·저장·알람·분석·대시보드를 전부 띄웁니다.

② 데이터 흐름

  1. 상시 전송 — Alloy가 메트릭(15초)·로그를 HTTPS 443(/vm/,/vl/)으로 보냄 → nginx가 TLS 종단 + basic-auth 후 내부 VictoriaMetrics/Logs로.
  2. 룰 평가 — vmalert가 사이트별 임계값 룰을 평가, 초과 지속 시 Alertmanager로 알림.
  3. webhook — Alertmanager가 내부에서 POST /webhook/alert 호출(외부 비공개).
  4. 로그 pull — app이 그 host의 직전 5분 로그를 VictoriaLogs에서 조회.
  5. AI 분석 — 원인/심각도/조치 분석 → DB 저장 → 대시보드 + 이메일/Slack.

서버 무응답(3분 미수신)은 vmalert가 아니라 app이 직접 감지해 같은 경로로 장애를 만듭니다.

③ 에이전트 3역할 (종류는 2 + 역할 1)

⑤ 보안

  • 전송 구간 TLS — 에이전트→중앙은 평문 8428/9428이 아니라 HTTPS 443 + basic-auth. 로그가 평문으로 인터넷을 타지 않음.
  • 무인증 포트 비공개 — VictoriaMetrics/Logs(8428/9428)는 컨테이너 내부에서만. 절대 공개 금지.
  • webhook 비공개 — /webhook/alert는 nginx에서 외부 차단(Alertmanager는 내부 호출). 분리 배포 시 WEBHOOK_SECRET 토큰.
  • 로그인 — 비밀번호 bcrypt 해시, 서명 세션 쿠키(Secure).
  • 방화벽 — 중앙은 443만 공개(에이전트 IP로 제한 권장).

라벨의미설정

host 이름 = 사이트 = 알람 라벨 = 로그 라벨을 일치시키는 게 핵심입니다(전 구간 같은 키로 추적).

기본은 서버 1대 = 사이트 1개(자동 생성). 여러 서버를 한 사이트로 합치려면 사이트의 매칭 패턴(예 web-prod-*)을, 보기만 묶으려면 group을 씁니다. (자세히는 ② 알람·운영)

⑦ AI 분석

알람마다 직전 5분 로그 + 맥락을 모아 LLM에 보내 구조화된 결과(원인 분류·상세·심각도·영향·즉시조치·재발방지·신뢰도)를 받습니다.

분석에 함께 주는 맥락

  • 아키텍처 메모 — 사이트에 적어둔 인프라 구성
  • 사이트 메모 — 운영 메모 + AI가 누적한 반복 원인(👍 시 승격)
  • 과거 분석 — 같은 서버의 최근 분석 결과

제공자 교체는 src/analyzer/ai_client.py 한 파일만 수정하면 됩니다(Timely GPT ↔ Claude 등).
